# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Pistea es la red social de esquiadores de toda España (27 estaciones): grabar el día con el GPS («traquear»), rankings, liga semanal, comunidad, perfil y el mapa 3D de cada estación. Producción: https://pistea.vercel.app. Todo el texto de interfaz, comentarios y documentación va en español. Además de este fichero, la documentación es `DEPLOY.md` (puesta en producción y motor del día), `SEGURIDAD.md` (auditoría, decisiones de seguridad y lo que le falta hacer a Miguel) y `app/PLAY_STORE.md`.

## Comandos
```
npm install            # una sola dependencia: @libsql/client
npm start              # http://localhost:3000; sin TURSO_* usa pistea.sqlite (o el de DATA_DIR)
npm test               # test.js: unas 170 comprobaciones de extremo a extremo (167 el 18-nov-2026)
node scripts/banco_seguimiento.js 12    # banco del motor del día: antes y después de tocar public/calc.js
```
- `npm test` arranca `server.js` en el puerto 3199 con una BD temporal, quita las variables de Turso, recorre la API como un navegador (cookie y cabecera `X-Pistea`) y reinicia el servidor para comprobar que nada se pierde. Es un guion lineal: no hay forma de lanzar una sola prueba; para probar algo suelto, levantar el servidor a mano y llamar a la API.
- **Nunca contra Turso.** `.env.local` (lo bajó la CLI de Vercel) lleva las credenciales de producción: `server.js` no lo lee, y así debe seguir (nada de `--env-file=.env.local`). Para trabajar en local con datos de prueba: `DATA_DIR=<carpeta temporal> PORT=… node server.js`, quitando `TURSO_DATABASE_URL` y `TURSO_AUTH_TOKEN` del entorno.
- En local, sin proveedor de correo, los enlaces de verificación y de recuperación salen en la consola (`[correo simulado] para <correo>`). Fuera de producción se admiten días de origen `sim` (sin traza GPS). El alta está limitada a 10 cuentas por hora y conexión: para sembrar muchas cuentas, `TRUST_PROXY=1` y una `X-Forwarded-For` distinta por cuenta.
- Datos de las estaciones, tras copiar los mapas (el orden importa): `python scripts/gen_invierno.py` (las miniaturas publicadas, con fondo de invierno de Sentinel-2 que baja de internet; `gen_miniaturas.py` es la versión con la ortofoto de verano) reescribe en `public/img/estaciones.json` la entrada de cada estación que hace (sin su `caja` ni su `dif`); después `node scripts/gen_seguimiento.js`, que escribe `public/seg/<id>.json` y añade a esas miniaturas su recuadro (`caja`), `node scripts/gen_dificultad.js` (la mezcla de colores, `dif`) y `node scripts/gen_pistas.js` (las pistas de cada ficha). `gen_seguimiento.js` necesita `mapas/` y `../../Estaciones3D/scripts/estaciones`. Nombre y color de las pistas vienen de las fuentes oficiales de cada estación, aplicadas en Estaciones3D (`scripts/estaciones/correcciones_pistas.json`); los itinerarios son «f» para el motor del día y «i» en la ficha. En esta máquina, Python es `C:\Users\migue\AppData\Local\Programs\Python\Python312\python.exe` (el de la Microsoft Store falla).
- App de Android (`app/`, Capacitor 8): `cd app && PISTEA_URL=https://… node sync.js && cd android && ./gradlew assembleDebug`. El envoltorio de Gradle se queda en la 8.14.3. La llave de firma (`app/android/pistea-upload.jks` y `keystore.properties`) no está en git.

## Arquitectura
- **Un servidor Node sin framework** (`server.js`, `http` a pelo). La API es la tabla `routes` (`'MÉTODO /api/ruta': async ({ req, res, u, q, b })`). `PUB` dice qué rutas no piden sesión. Toda escritura exige la cabecera `X-Pistea: 1` (anti-CSRF): `api()` de `app.js` y los clientes de las pruebas la ponen. La sesión va en una cookie `HttpOnly` (`__Host-pistea` en producción, `pistea_s` en local). Los límites de intentos se guardan en la tabla `hits`, en la BD, para que sobrevivan a reinicios y a varias instancias.
- **BD libSQL**: Turso en producción y un fichero SQLite en local. Las tablas se crean al arrancar (`SCHEMA`, luego `ALTERS` e `INDEXES`, de forma idempotente). Una columna nueva se añade a `ALTERS`; nunca se cambian las tablas a mano. Con varias escrituras que deben ir juntas se usa `atomic` (transacción).
- **El mismo servidor sirve todo lo estático**: `index.html` (con una CSP estricta, `script-src 'self'`), `/app.js` y `/calc.js` (sin caché, para que no quede una versión vieja con una página nueva), `/img`, `/seg`, `/fonts`, `/3d/` (los mapas 3D de `MAPS_DIR`, por defecto `mapas/`), las páginas legales de `legal.js`, `/healthz` y el manifiesto.
- **La página es una SPA en un solo fichero** (`public/app.js`). El estado está en `st`, las pestañas son las vistas de `V` (`est`, `com`, `rec`, `yo`), `render()` rehace `#m` entero y las fichas se abren con `ov()`/`ov0()`. Como la CSP prohíbe el JavaScript dentro del HTML, el HTML no lleva `onclick`: lleva `data-c` (clic), `data-s` (enviar), `data-i` (escribir) y `data-ch` (cambiar), con «acción|argumento|…». Solo se ejecuta lo que está en la lista `ACT`, así que una acción nueva hay que añadirla ahí. El alta guiada (`OB`) y «Editar perfil» comparten las piezas `FD` sobre un borrador `st.dr`.
- **El motor del día** (`public/calc.js`, UMD) es el mismo código en el navegador (cifras en directo) y en el servidor. Al guardar un día con GPS, el servidor lo recalcula desde la traza (`checkTrace` y `new Calc(stationOf(id))`) y descarta las cifras del móvil: es el antitrampas. `stationOf` junta `public/seg/<id>.json` con el relieve `mapas/estaciones/<id>/data/dem.u16d`; sin relieve, usa la altitud del GPS, que es peor. Por dentro, el motor proyecta a metros locales, filtra con Kalman y Doppler, detecta remontes y subidas, y asigna las pistas con Viterbi, con un estado propio para el freeride. Está explicado al principio del fichero. Salió de `filter.js` y `ski.js` de Valdesquí 3D, pero ya va por su cuenta.
- **Rankings** (`rankRows`, `posOf`): los periodos de `WIN` son ventanas móviles (hoy = 24 h, semana = 7 días, temporada = 365 días) y las métricas están en `MX`. La liga es el percentil del desnivel de la semana (Bronce, Plata, Oro y Diamante para el 10 % de arriba). La racha cuenta semanas seguidas con días. En público solo salen las cuentas verificadas, ni ocultas ni suspendidas (`pubCond`), sin bloqueos, y en producción sin días `sim`.
- **Pasaporte de pistas, récords por pista y Pistea Wrapped** (17-nov-2026). Al guardar un día GPS, su desglose (`detail.runs`, del motor del servidor) se reparte en la tabla `passes`: una fila por pista y día, con las bajadas que la tocaron, los metros (cuenta a partir de 100, `PASS_MIN`) y la máxima en ella. Desde el desglose v3, cada tramo lleva su máxima (`[color, pista, metros, km/h]`); en los días anteriores vale la de la bajada si fue casi entera por esa pista. `passes` se rellena una vez al arrancar con los días antiguos y se borra con su día (moderación) o su cuenta. Rutas: `GET /api/passport` (pistas selladas por estación, coronas de la temporada y puesto entre coleccionistas), `/api/piste` (clasificaciones de velocidad y bajadas de una pista), `/api/records` (el más rápido de cada pista de una estación) y `/api/wrapped` (la temporada desde el 1 de julio). `POST /api/days` devuelve `nov` (pistas nuevas, mejores marcas y coronas) para el resumen del día. El progreso se mide contra `public/img/pistas.json`; en los dominios compartidos (La Molina y Masella, Astún y Candanchú) `canon` lleva cada fila a la ficha de su estación. En la app: `ppCard`/`ppView` (perfil y pasaporte de una estación), `pisteView` (desde la lista de pistas de cada ficha), `recPistes` (pestaña Récords con una estación elegida), `wrapped` (historias; `wrShare` hace la imagen de 1080 × 1920) y `novHtml`. La velocidad es la del GPS del móvil mantenida dos segundos; la ficha de pista recuerda esquiar a la velocidad que se pueda controlar.
- **La lista de estaciones está repetida**: `STATIONS` en `server.js`, `S` en `app.js`, `estaciones_geo.json` (antitrampas), `public/seg/`, `public/img/` (`estaciones.json`, `fotos.json`, `pistas.json` y la miniatura `.webp`) y los mapas de `mapas/estaciones/`. Añadir una estación toca todo eso.
- **Mapas 3D**: `mapas/` es una compilación del motor común `Documents\Estaciones3D` (`web/dist/app`). Se cambian allí, no aquí. Cada vista descarga entre 40 y 75 MB, y el mayor fichero pesa unos 21 MB. En producción se publican aparte, en Cloudflare Pages (`MAPS_URL`, por defecto https://pistea-mapas.pages.dev en Vercel). La app abre el `iframe` en la dirección que da `/api/config` (`maps`), y la CSP (`frame-src`) y el permiso de ubicación del `iframe` se calculan a partir de ella. `/3d/…` redirige allí, salvo `dem.u16d`, que el servidor sigue sirviendo porque lo usa el motor del día también en el navegador. Sin `MAPS_URL` (en local, en las pruebas o con Docker), el 3D lo sirve este servidor. Los mapas se publican con wrangler (comando en `DEPLOY.md`) lanzado desde fuera de esta carpeta: dentro, wrangler 4 reescribe `package.json` y `.gitignore` y crea `wrangler.jsonc` para convertir Pistea en un Worker.

## Despliegue
- **Vercel**, conectado a GitHub: cada `git push` a `main` se publica en producción en un par de minutos. Por tanto, subir es publicar, y solo se sube cuando Miguel lo pide. `vercel.json` manda **todas** las rutas a la función `server.js` (`@vercel/node`). La función lleva `public/**` y los relieves, y `.vercelignore` deja fuera de la subida `app/`, `scripts/` y los mapas, salvo `dem.u16d`. Vercel guarda la función de cada despliegue y el plan gratuito da 10 GB para todas: el 16-nov-2026, con los mapas dentro, se llegó a unos 18 GB. Hay que vigilar que nada pesado vuelva a la función. En Vercel, sin `TURSO_*`, la API responde 503 en vez de escribir en el disco temporal. Variables de producción: ver `DEPLOY.md`.
- Hay una alternativa preparada con **Docker** (`Dockerfile`, `docker-compose.yml`, `Caddyfile` con HTTPS de Let's Encrypt y `TRUST_PROXY=1`).

## Cosas que no se ven en el código
- El repositorio es **privado** (`MiguelUFV/pistea`). Vive dentro de la carpeta de Valdesquí 3D, pero es un git aparte: desde la carpeta de arriba nunca `git add -A`.
- Commits en español, directos a `main`.
- El plan gratuito de Vercel no permite uso comercial: antes del lanzamiento hace falta el plan Pro o un servidor propio (lo pendiente está en la lista de `SEGURIDAD.md`). La cuenta de Vercel tiene otros 8 proyectos de Miguel que comparten la cuota.
- Atribución obligatoria en pantalla: IGN/CNIG (CC BY 4.0) y OpenStreetMap (ODbL) en mapas y miniaturas; las fotos de estación con su autor y licencia (`public/img/fotos.json`); la portada es CC0 (Thomas Röggla).
- Hay que distinguir lo medido de lo interpretado: el freeride y las pistas de cada bajada son la interpretación del motor sobre el GPS. Los textos no deben venderlos como exactos.
